# Codyssey Mission 3 — Mini NPU Simulator

MAC(Multiply-Accumulate) 연산으로 3×3~25×25 패턴을 판별하는 Python 콘솔 시뮬레이터.

## 실행 방법
실행 후 모드 선택: `1` 사용자 입력(3×3) / `2` data.json 분석

## 진행 상황
- [x] MAC 연산 + epsilon 판정
- [x] 모드 1: 입력 검증 → MAC → 판정 → 성능 측정
- [x] 모드 2: data.json 로드 / 라벨 정규화 / PASS·FAIL
- [x] 결과 리포트 (FAIL 원인 분석 + O(N²) 시간 복잡도)

## 구현 요약

### 라벨 정규화
프로그램 내부에서는 표준 라벨 두 가지(`Cross`, `X`)만 사용한다. data.json의 expected 값은 `+`, `x`, `cross`처럼 표기가 제각각이고, filter 키도 `cross`/`x`로 들어온다. 이를 비교 전에 모두 표준 라벨로 변환한다: `+`와 `cross`는 `Cross`로, `x`는 `X`로 정규화한다. 정규화 시 앞뒤 공백 제거와 소문자 변환을 먼저 적용해 표기 흔들림(`X`, ` cross ` 등)에도 대응한다.

### MAC 연산
입력 패턴과 필터를 같은 위치끼리 곱하고 모두 더하는 이중 반복문으로 구현했다. 외부 라이브러리(NumPy 등)는 사용하지 않았다. n×n 크기에 대해 안쪽 루프 몸통이 정확히 N²번 실행되며, 이 횟수가 곧 시간 복잡도의 근거가 된다.

### 동점 처리 정책 (epsilon)
두 필터 점수를 비교할 때 부동소수점 오차를 고려해 허용오차 기반 정책을 적용한다. `abs(score_cross - score_x) < 1e-9`이면 두 점수를 같은 것으로 간주하고 `UNDECIDED`로 판정한다. 이 정책이 없으면 이론상 같아야 할 두 값이 부동소수점 오차 때문에 다르게 비교되어 잘못된 판정이 나올 수 있다.

## 결과 리포트

### 테스트 결과
전체 8개 케이스 중 7개 PASS, 1개 FAIL로 나타났다.

### 실패 원인 분석
유일한 실패 케이스는 `size_13_1`이다. 이 패턴은 Cross 필터로 계산하면 점수가 정확히 `0.9`, X 필터로 계산하면 `0.8999999999999999`가 나오도록 설계되었다. 두 값의 차이는 약 1.1e-16으로 허용오차(1e-9)보다 훨씬 작기 때문에, epsilon 정책에 따라 두 점수는 동점으로 간주되어 판정이 `UNDECIDED`가 된다. 그러나 이 케이스의 expected는 `X`이므로, 판정(UNDECIDED)과 기대값(X)이 일치하지 않아 FAIL로 처리된다.

이 실패는 데이터 오류나 로직 버그가 아니라 수치 비교 정책의 의도된 결과다. 실패 원인을 세 범주로 분류하면, 데이터/스키마 문제(키·크기 불일치)도 아니고 로직 문제(MAC 계산 오류)도 아닌, 순수한 수치 비교 문제에 해당한다. X 필터 점수가 부동소수점 누적 오차로 `0.9`에 미세하게 못 미쳐 발생한 동점이며, 이는 부동소수점 연산이 가진 본질적 특성을 보여주는 사례다.

### 나머지 케이스가 PASS인 이유 (정규화/epsilon)
나머지 7개 케이스가 모두 PASS한 데에는 라벨 정규화가 결정적이었다. expected 값에 `+`, `x`, `cross`가 섞여 있었지만, 정규화를 통해 모두 `Cross`/`X` 표준 라벨로 변환한 뒤 비교했기 때문에 표기 차이로 인한 오탐(false FAIL)이 발생하지 않았다. 만약 정규화 없이 판정 결과(`Cross`/`X`)와 원본 expected(`+`/`cross`)를 직접 비교했다면, 실제로는 맞는 판정임에도 문자열이 달라 FAIL로 잘못 처리되었을 것이다.

### 성능 분석 및 시간 복잡도 (O(N²))
크기별 MAC 연산 시간을 10회 반복 측정한 평균은 다음과 같다.

| 크기(N×N) | 평균 시간(ms) | 연산 횟수(N²) |
|-----------|--------------|--------------|
| 3×3       | 0.002        | 9            |
| 5×5       | 0.003        | 25           |
| 13×13     | 0.013        | 169          |
| 25×25     | 0.045        | 625          |

MAC 연산은 n×n 크기의 패턴과 필터를 위치별로 곱하고 더하는 이중 반복문이므로, 연산 횟수는 정확히 N²에 비례한다. 표에서 연산 횟수는 9 → 25 → 169 → 625로 증가하는데, 이는 각각 3² → 5² → 13² → 25²로 크기의 제곱과 정확히 일치한다. 측정된 평균 시간도 연산 횟수 증가에 비례해 늘어나는 경향을 보이며, 이는 MAC 연산의 시간 복잡도가 O(N²)임을 실측으로 뒷받침한다. 패턴 크기가 커질수록 연산량이 제곱으로 폭증하기 때문에, 대규모 필터를 다루는 실제 AI 연산에서는 이러한 반복 연산을 병렬 처리하는 NPU 같은 전용 하드웨어가 필요해진다.
